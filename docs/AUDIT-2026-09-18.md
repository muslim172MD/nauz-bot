# Технический аудит репозитория — 2026-09-18

## Объект

Репозиторий: `muslim172MD/nauz-bot`.

## Исходное состояние

Репозиторий был небольшим и рабоче-ориентированным: один основной Python-файл, `requirements.txt`, `Procfile`, `runtime.txt` и минимальный README.

Выявлены основные риски:

1. **Приватность.** Диалоги автоматически сохранялись в JSON-файлы. Для проекта в сфере здравоохранения это создаёт ненужный риск хранения чувствительных данных.
2. **Передача чувствительных данных.** Не было явного барьера перед отправкой текста во внешний LLM API.
3. **Асинхронность.** Синхронный Anthropic-клиент вызывался из async Telegram handlers и мог блокировать event loop.
4. **Длинные отчёты.** Telegram имеет ограничение длины сообщения; длинный отчёт мог не отправиться.
5. **Конфигурация.** Не было ранней проверки обязательных переменных окружения.
6. **Репозиторий.** Отсутствовали `.gitignore`, `.env.example`, CI, тесты и документация по безопасности.
7. **Процесс разработки.** Не было формализованного PR-checklist и автоматической проверки базовой работоспособности.

## Что исправлено в ветке аудита

- включён `AsyncAnthropic`;
- добавлена проверка конфигурации при старте;
- локальное сохранение диалогов выключено по умолчанию;
- добавлен базовый фильтр явных маркеров идентифицирующих данных пациентов;
- в системный промпт добавлены правила приватности;
- добавлена команда `/privacy`;
- длинные ответы режутся на безопасные для Telegram части;
- внутренние инструкции больше не маскируются под пользовательские сообщения;
- добавлены `.gitignore` и `.env.example`;
- README превращён в рабочую инструкцию;
- добавлены `SECURITY.md`, unit-тесты, CI и PR-template;
- правила агентов уточнены.

## Проверка истории секретов

В просмотренных изменениях `nauz_bot.py` реальные токены не обнаружены: ранняя версия содержала только текстовые placeholders, затем конфигурация была переведена на переменные окружения.

Это не заменяет специализированное сканирование всей git-истории. Для production рекомендуется дополнительно включить secret scanning в GitHub и ротировать любой ключ при малейшем сомнении.

## Что сознательно не менялось автоматически

- версия модели Anthropic не заменялась на другую без проверки production-аккаунта;
- зависимости не обновлялись массово без отдельного совместимого теста;
- текущая схема deployment (`Procfile` + `runtime.txt`) сохранена, чтобы не ломать существующий хостинг;
- не включено постоянное хранилище состояния: это требует отдельного решения по безопасности и инфраструктуре.

## Следующие шаги

1. Дождаться зелёного CI на pull request.
2. Проверить production secrets в хостинге.
3. Выполнить smoke-test Telegram: `/start`, обычный ответ, `/privacy`, `/report`.
4. После smoke-test слить PR.
5. Отдельно решить вопрос хранения диалогов и политики retention.
6. Проверить актуальность библиотек и модели Anthropic в staging.
