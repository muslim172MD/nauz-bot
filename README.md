# НАУЗ Bot

Telegram-бот Национальной Ассоциации Управленцев Сферы Здравоохранения (НАУЗ).

Бот проводит структурированное интервью с управленцами здравоохранения, помогает выявить цели и проблемы и формирует итоговый профиль.

## Что делает бот

- проводит интервью по одному вопросу за раз;
- собирает контекст о роли, организации, цифровизации, кадрах, финансах и управленческих приоритетах;
- формирует итоговый структурированный отчёт;
- предупреждает о недопустимости передачи идентифицирующих данных пациентов;
- по умолчанию не сохраняет диалоги на локальный диск.

## Быстрый запуск

Требуется Python 3.11.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Задайте переменные окружения:

```bash
export TELEGRAM_TOKEN="..."
export ANTHROPIC_API_KEY="..."
export ANTHROPIC_MODEL="claude-opus-4-5"
python nauz_bot.py
```

Не коммитьте реальные токены в GitHub.

## Переменные окружения

| Переменная | Обязательная | Назначение |
| --- | --- | --- |
| `TELEGRAM_TOKEN` | да | токен Telegram-бота |
| `ANTHROPIC_API_KEY` | да | API-ключ Anthropic |
| `ANTHROPIC_MODEL` | нет | модель Anthropic |
| `SAVE_DIALOGS` | нет | `false` по умолчанию; включает локальное сохранение диалогов |
| `DIALOGS_DIR` | нет | каталог локального сохранения, по умолчанию `data/dialogs` |
| `LOG_LEVEL` | нет | уровень логирования, по умолчанию `INFO` |

## Приватность

Репозиторий публичный. В коде не должно быть секретов, токенов и данных пациентов.

Бот не должен запрашивать или отправлять во внешний ИИ идентифицирующие данные пациентов. Реализована консервативная проверка явных маркеров таких данных, но она не заменяет организационные меры и полноценный DLP-контур.

Локальное сохранение диалогов отключено по умолчанию. Если `SAVE_DIALOGS=true`, ответственность за защищённое хранение, сроки хранения и доступ лежит на владельце инфраструктуры.

Подробнее: [SECURITY.md](SECURITY.md).

## Структура репозитория

- `nauz_bot.py` — приложение Telegram;
- `requirements.txt` — зависимости;
- `Procfile` — запуск worker-процесса;
- `runtime.txt` — версия Python для текущего хостинга;
- `AGENTS.md` — правила работы ИИ-агентов;
- `tests/` — минимальные автоматические проверки;
- `.github/workflows/ci.yml` — CI;
- `docs/AUDIT-2026-09-18.md` — результаты технического аудита.

## Проверка перед изменениями

```bash
python -m py_compile nauz_bot.py
python -m unittest discover -s tests -p "test_*.py"
pip check
```

## Рабочий процесс

1. Изменения делаются в отдельной ветке.
2. Открывается pull request.
3. CI должен пройти успешно.
4. Проверяется отсутствие секретов и данных пациентов.
5. Только после проверки изменения попадают в `main`.

## Ограничения текущей версии

- хранение состояния идёт в памяти процесса;
- при перезапуске активные диалоги не восстанавливаются;
- сохранение диалогов, если включено, файловое и не предназначено для медицинских данных;
- production smoke-test зависит от реальных Telegram/Anthropic credentials и выполняется отдельно.
